# SPEC-007 — Головна зі статистикою та станом API

Статус: Реалізовано для перевірки. Залежності: 002, B-04. Користувач бачить загальний розмір автопарку та переходить до потрібного розділу.

## Обсяг

#/: чотири картки «Перевізники», «Автобуси», «Маршрути», «Водії» із загальними кількостями та посиланнями. GET /health — індикатор доступності API. Не називати його перевіркою MySQL: поточна реалізація лише повертає {"status":"ok"}.
Показники завантажуються незалежно. Стан картки: loading, number (включно з реальним 0), error із «—». Кнопка «Оновити» повторює читання. Після змін в інших розділах при поверненні отримати актуальні значення.

## Рішення щодо підрахунку — обов’язкова контрольна точка

Вибране рішення без нового ендпоінта: companies/buses/routes рахуються довжиною повного масиву зі відповідного GET.
Для водіїв виконуються послідовні GET `/drivers?limit=100&offset=0,100,...` до сторінки з менше ніж 100 записами.
Для рівно 100 водіїв додатковий запит повертає порожню сторінку. Будь-яка помилка скасовує суму і показує `—`;
часткова сума не відображається. Підрахунок може бути неточним при одночасних змінах БД.

Companies/buses/routes: довжина повних масивів підтверджується актуальним API. Для водіїв total наразі немає.

Рекомендовано погодити GET /stats з відповіддю {"companies":5,"buses":10,"routes":10,"drivers":10}. Це пропозиція розширення бекенду, не готовий ендпоінт. У разі вибору він потребує окремої реалізації, OpenAPI й перевірки.

Допустимий варіант без нового ендпоінта для малого навчального набору: послідовно читати /drivers?limit=100&offset=0,100,... до сторінки з <100 записами й підсумувати. Для рівно 100 потрібен ще один запит. За помилки не показувати часткову суму як загальну; при повторі починати з offset=0. При виході скасовувати читання. За одночасних змін цей підрахунок не є атомарним і може бути неточним; обмеження потрібно явно погодити.

Перед кодом записати вибраний варіант і його контракт у цю spec. Поки рішення не прийнято, ітерація частково заблокована; не підміняти загальну кількість розміром поточної сторінки, не вигадувати дані. Інші ітерації можуть продовжуватися.

## Дизайн

Заголовок «Огляд автопарку», пояснення, кнопка оновлення та індикатор API. Сітка карток 4 колонки на ≥1024 px, 2 на 640–1023 px, 1 нижче. Велике число, підпис, стрілка переходу; без відсотків зростання, бо історії даних немає. Індикатор має текст, не лише зелену/червону крапку.

## Задачі

- [x] Погоджено джерело кількості водіїв і зафіксовано послідовний обхід сторінок.
- [x] Реалізовано картки й незалежні стани.
- [x] Додано health та оновлення показників.
- [ ] Показники контрольного seed перевірені на реальному API частково; 0/100/101 перевірено Playwright-тестами.

## Критерії приймання

- S007-AC-01: для чистого наданого seed видно 5/10/10/10, кожна картка веде до відповідного списку.
- S007-AC-02: на наборі >20 водіїв число загальне; для варіанта обходу сторінок перевірено 0/100/101 запис.
- S007-AC-03: помилка джерела не перетворюється на 0 чи часткову кількість; незалежні успішні показники залишаються доступними.
- S007-AC-04: /health=200 дає текст «API доступне»; збій — повідомлення про неможливість перевірити, без твердження про стан БД.
- S007-AC-05: повернення після створення/видалення оновлює числа; 360 px і клавіатурні переходи працюють.

Готовність: джерело даних визначене й усі AC виконані. Непогоджений mock статистики не закриває ітерацію.
