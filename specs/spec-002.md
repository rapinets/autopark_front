# SPEC-002 — Списки сутностей із дизайном

Статус: Реалізовано для перевірки. Залежності: 001, виправлені GET списків (B-01). Користувач переглядає всі основні сутності та знаходить водія на поточній сторінці.

## Обсяг і API

| Екран | Запит | Колонки |
|---|---|---|
| #/companies | GET /companies/ | Назва, телефон |
| #/buses | GET /buses/ | Номер, модель, місця, перевізник |
| #/routes | GET /routes/ | Номер, назва, відстань, км |
| #/drivers | GET /drivers?limit=&offset= | ПІБ, телефон, посвідчення, перевізник |

Відображати порядок API: name, plate_number, number, full_name + id відповідно. Не вводити клієнтське сортування, яке змінює лише одну сторінку водіїв. Допуски переглядаються в картці водія в 003: загального GET /assignments немає.

## Поведінка

Чотири стани G-01 для кожного списку. Кнопка «Оновити» повторює GET. Немає кнопок ще не реалізованих операцій створення/редагування.
Пагінація водіїв: P=10/20/50, початково 20; запит limit=P+1. Показати перші P, hasNext = отримано >P; наступний offset += P, попередній max(0,offset−P). Зміна P скидає offset. Немає кількості всіх сторінок без total.
Пошук: trim запиту, підрядок без регістру в full_name, phone, license_number лише перших P рядків. Додатковий рядок не бере участі. Підказка «Пошук лише на поточній сторінці»; нуль збігів не вимикає Next, якщо hasNext=true.
Рекомендований формат збереження стану: #/drivers?limit=20&offset=0&q=...; неправильні параметри нормалізуються. Запит пошуку зберігається при переходах. Старі відповіді не підміняють поточну сторінку.

## Дизайн

Заголовок + короткий опис; toolbar пошуку/розміру сторінки водіїв; таблиця з чіткими заголовками й відступами. Нижче 768 px — картки з labels. ПІБ/назви переносяться, довгі значення не ламають ширину. Loading повторює форму майбутніх рядків; empty має пояснення; error — кнопку повтору.

## Критерії приймання

- S002-AC-01: усі чотири списки відображають реальні дані й усі чотири стани; company_name видно для автобуса/водія.
- S002-AC-02: при P=10 і 11 записах видно 10, Next активна; наступний offset=10 і 11-й запис не пропущений. При рівно 10 записах Next неактивна. Повторити для 20/21 та 50/51.
- S002-AC-03: пошук не показує додатковий P+1 рядок; очищення відновлює сторінку; hasNext не залежить від фільтра.
- S002-AC-04: direct link, Назад/Вперед та зміна P відновлюють коректний стан; offset не від’ємний.
- S002-AC-05: 360 px і довгі значення не приховують дані; швидкі переходи не змішують результати.

Готовність: AC виконані на реальних списках; перевірка next-page потребує більше 10 водіїв, вихідного seed для цього недостатньо.
