# SPEC-001 — Основа застосунку та єдиний дизайн

Статус: Реалізовано для перевірки. Залежності: [спільні правила](README.md), API_BASE_URL, актуальна OpenAPI. Результат: користувач може відкрити застосунок, перейти між розділами та перевірити доступність API.

## Обсяг

- HTML/CSS/JS-проєкт, ES modules, спільна оболонка.
- Hash-router: #/, #/companies, #/buses, #/routes, #/drivers; невідомий шлях показує зрозумілу сторінку.
- Sidebar/мобільне меню, активний розділ, заголовок, контейнер контенту.
- API-клієнт: base URL, JSON, статуси, порожня відповідь 204, мережева помилка. GET /health використовується для перевірки підключення.
- Мінімальний README із запуском HTTP-сервера та адресою API.

## Дизайн

Реалізувати DS-01 зі спільного README. Підготувати кнопки primary/secondary/danger, input/select, картку, заголовок сторінки, таблицю, skeleton, empty/error блоки, повідомлення й діалог підтвердження. Стани компонентів: hover, focus, disabled, loading, invalid.
На головній поки показати навігаційний огляд без вигаданих лічильників. Нереалізовані сторінки позначати явно, не показувати фальшиві записи.

## Критерії приймання

- S001-AC-01: відкриття прямого #/drivers і перезавантаження показують потрібний розділ; Назад/Вперед коректно змінюють екран.
- S001-AC-02: на 360/768/1440 px навігація доступна; сторінка не має горизонтального overflow; активний пункт видимий.
- S001-AC-03: компоненти мають клавіатурний фокус, labels і контраст DS-01; меню закривається після вибору й через Escape.
- S001-AC-04: /health=200 відображається як успіх; мережева помилка має окремий текст; 204 у тесті клієнта не спричиняє JSON-помилку.
- S001-AC-05: рядок з HTML у компоненті повідомлення відображається текстом.

## Поза обсягом / готовність

CRUD і справжні списки — наступні ітерації. Готовність: усі AC виконані, запуск відтворюється за README. Якщо API недоступне, верстку можна завершити, але AC-04 для реального API залишається відкритим.
