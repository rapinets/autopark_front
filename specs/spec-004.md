# SPEC-004 — Форми створення

Статус: Реалізовано для перевірки. Залежності: 003, B-01–B-03. Користувач додає перевізника, автобус, маршрут і водія.

## Обсяг

Маршрути #/companies/new, #/buses/new, #/routes/new, #/drivers/new. Router перевіряє /new до динамічного /:id. Кнопка «Додати» у відповідному списку. POST із JSON за контрактом README.
Поля точно відповідають V-01. Для автобуса та водія — select перевізника з GET /companies/, label=name, value=id. Без перевізників — пояснення й посилання на створення замість активної форми автобуса; для водія також заблоковане збереження. Помилка списку не видається за порожнечу.
Після 201 показати успіх і перейти до картки створеного запису за id відповіді. Якщо повторне читання неуспішне, зберегти повідомлення про успішне створення й запропонувати повтор GET. Не створювати запис повторно автоматично.

## Дизайн й UX

Окрема сторінка форми: заголовок, breadcrumb, картка до 760 px, одна колонка на mobile, за потреби дві на desktop. Видимі labels, підказки діапазонів, помилки під полями; в кінці «Створити» й «Скасувати». Телефон type=tel, посвідчення/номер маршруту — text. Числові поля не приймають дробові значення.
Помилки перевіряти після першого виходу з поля та при submit; після невдалого submit фокус на першому невалідному полі. Не показувати «червону» порожню форму ще до взаємодії. При надсиланні spinner і блокування повтору.

## Критерії приймання

- S004-AC-01: валідна форма кожної сутності створює один запис; id і company_name не підміняють вхідні поля; company_id надсилається числом.
- S004-AC-02: для кожного текстового поля перевірені min−1/min/max/max+1 після trim; рядок лише з пробілів відхиляється. Числа перевірені на межах і з дробами/порожнім введенням.
- S004-AC-03: без перевізників автобус не надсилається; помилка завантаження має повтор; вибір зниклого перевізника обробляє BR-B1/BR-D1.
- S004-AC-04: дублікати name/plate_number/number/license_number показують detail; 422 прив’язане до поля, значення збережені. Текст BR-B2 звірений із сервером.
- S004-AC-05: подвійний клік не створює два POST; успішний POST + невдалий GET не пропонує повторне створення.
- S004-AC-06: форма доступна з клавіатури та на 360 px, скасування не виконує POST.

Готовність: усі чотири сценарії підтверджені API; якщо БД досі має VARCHAR(13) телефона або UNIQUE phone, це блокер відповідності ТЗ, не привід звузити UI непомітно.
