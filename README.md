# Автопарк — фронтенд

Статичний HTML/CSS/JavaScript застосунок на ES modules без React/Redux.

## Структура

- `index.html` — точка входу.
- `js/app.js` — оболонка та реєстр hash-route.
- `js/router.js` — hash-router із direct-link та query-параметрами.
- `js/api/client.js` — базова адреса, timeout та обробка Fetch-відповідей.
- `js/pages/` — списки, картки, створення й редагування.
- `js/utils/validation.js` — спільні валідатори.
- `js/components.js` — заголовки, стани й діалог підтвердження.
- `styles/tokens.css` і `styles/components.css` — дизайн-система.
- `tests/` — Playwright перевірки ітерацій.

## Передумови

- Python 3 для локального HTTP-сервера.
- Node.js 22+ для Playwright-перевірок.
- Доступ до API `https://autopark-back.onrender.com`.

## Запуск

1. Відкрийте каталог проєкту в терміналі.
2. Запустіть HTTP-сервер:
   ```powershell
   py -m http.server 4173
   ```
3. Відкрийте `http://localhost:4173/`.

Не відкривайте `index.html` через `file://`: ES modules і Fetch API потребують HTTP.

## API

Адреса API налаштована в одному місці: `js/api/client.js`.

Поточна адреса: `https://autopark-back.onrender.com`.

Для зміни адреси змініть `API_BASE_URL`. Не додавайте секрети до браузерного коду.

Приклад локального origin для CORS: `http://localhost:4173`. Сервер має дозволяти
GET/POST/PUT/DELETE із цього origin або дозволяти його через налаштований CORS.
Перевірка підключення виконується через `GET /health`; вона перевіряє доступність API,
а не стан MySQL. Бази даних не змінюйте локальними тестами.

## Маршрути

- `#/`
- `#/companies`
- `#/buses`
- `#/routes`
- `#/drivers`
- `#/companies/:id`
- `#/buses/:id`
- `#/routes/:id`
- `#/drivers/:id`
- `#/drivers/:id/edit`
- `#/companies/new`
- `#/buses/new`
- `#/routes/new`
- `#/drivers/new`

Невідомий hash показує сторінку «Сторінку не знайдено».

## Узгоджені помилки (iтерація 008)

API-клієнт має timeout 15 секунд. Мутаційний timeout не оголошує невизначений
результат успіхом чи невдачею і пропонує актуалізувати дані. Спеціальні 409
показують detail сервера; загальний IntegrityError показується як операційна
помилка, а не прив'язується до конкретного поля.

## Головна зі статистикою (iтерація 007)

Картки головної рахують повні масиви перевізників, автобусів і маршрутів.
Для водіїв застосовується послідовне читання сторінок по 100.
Жодного ендпоінта `/stats` або фіктивної загальної кількості не додано.

## Допуски водія (iтерація 006)

Блок допусків на `#/drivers/:id` завантажує каталог маршрутів і допуски
поточного водія. Доступні маршрути обчислюються за `route_id`.
Додавання виконує `POST /assignments`, скасування — з підтвердженням через
`DELETE /assignments/{driver_id}/{route_id}`.

## Редагування й видалення водія (iтерація 005)

- Редагування: `#/drivers/:id/edit`
- Видалення доступне зі списку та картки водія.
- Видалення підтверджується діалогом і виконує один `DELETE /drivers/{id}`.

## Створення (iтерація 004)

- `#/companies/new`
- `#/buses/new`
- `#/routes/new`
- `#/drivers/new`

Форми використовують V-01 із спільного модуля валідації. Автобус і водій
отримують перевізників через `GET /companies/`; без перевізників збереження
недоступне.

## Списки (iтерація 002)

Чотири розділи завантажують реальні списки через GET API.
Для водіїв підтримуються розмір сторінки 10/20/50, локальний пошук
на поточній сторінці та P+1 пагінація. Параметри зберігаються в hash:

`#/drivers?limit=20&offset=0&q=`

## Контракт і перевірка залежностей

Актуальна OpenAPI завантажена з `https://autopark-back.onrender.com/openapi.json`.
Для поточної ітерації підтверджено:

- шляхи `/companies/`, `/buses/`, `/routes/`, `/drivers`, `/health`;
- `/drivers` підтримує `limit` 1–100 і `offset` >= 0;
- схеми створення й оновлення сутностей узгоджені зі спільними правилами;
- `/health` повертає `{"status":"ok"}`;
- CORS дозволяє GET із іншого origin: фактичний preflight відповів 200;
- розбіжності B-02–B-05 серверної БД у поточній ітерації не перевіряються;
- окремий ендпоінт загальної кількості або статистика не додані.

## Тестовий набір і перевірки

Для браузерних перевірок тимчасово встановіть:

```powershell
npm install --no-save @playwright/test
npx playwright install chromium
```

При запущеному HTTP-сервері запустіть:

```powershell
npx playwright test tests/ --reporter=line
```

Не запускайте реальні POST/PUT/DELETE проти робочих даних.
Руйнівний каскадний сценарій має виконуватись лише на окремому тестовому наборі.
Для тестового наповнення:

1. Очистіть лише виділену тестову БД.
2. Створіть перевізника, автобус, маршрут і водія через UI або API.
3. Додайте допуск, скасуйте його, додайте знову.
4. Видаліть тестового водія.
5. Перевірте MySQL: допуски водія видалені, маршрут залишився.
6. Перевірте `GET /drivers/{id}` і очікуваний 404.

## Рішення статистики

Нового `/stats` не створено. Перевізники, автобуси й маршрути рахуються довжиною
повного GET-масиву. Водії рахуються послідовними сторінками по 100 записів:
`GET /drivers?limit=100&offset=0,100,...`. Реальний підрахунок під час одночасних
змін БД може бути неточним.

## Відомі обмеження

- Реальні руйнівні мутації не виконані на робочій БД.
- Каскад видалення допусків у MySQL не підтверджений локально.
- Не перевірено реальний Postgre/MySQL індекс/унікальність дубліката в поточному environment.
- Повний наскрізний сценарій на тестовій БД потребує окремого тестового API.
